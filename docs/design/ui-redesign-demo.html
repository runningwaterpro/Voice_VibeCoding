把「桥接」当成仪器面板，而不是设置长页

从用户任务出发：先回答「接上了吗 / 能说话吗 / 哪里坏了」，再给键位与增益。 界面主体是遥控器 + 双电平 + 一键修复， 细节配置收进侧栏，避免现在小米页 4000 行里信息挤成一团。

当前界面的主要问题（对照）

  • 一切信息平铺：连接、波形、声卡、修复按钮、键位、增益同级出现
  • 术语偏系统（ATVV / WinUHid / 桥接），用户任务被淹没
  • 异常时才需要的「修复」常驻，增加噪音
  • 遥控器只是插图，不是可操作的中心对象
  • 垂直空间被标尺和说明文字吃掉，全屏也放不下遥控器

重设计原则

  • 一句话状态放在最顶：现在能不能用
  • 遥控器是主角：按键与语音键有即时反馈
  • 双电平一行一条：输入定增益，送声防削波
  • 有问题才出现主修复按钮
  • 主机细节 / 高级诊断默认折叠，需要时再开

色板与字体

石墨机箱底 + 信号青绿（就绪）+ 琥珀（注意）+ 砖红（故障）。数字用等宽，正文用系统中文 UI 字体。

增益

高级：进程日志、驱动修复、Host 原始字段——默认不占主视线。

交互：状态机

未连接 → 连接中 → 就绪 → 按住说话。异常从就绪分叉，主按钮变为「修复语音通道」，修好回就绪。

交互：增益

只看「输入」决定加不加；只看「送声」决定要不要降。拧增益时输入条不动、送声条动。
